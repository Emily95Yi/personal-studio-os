# Review 与 Roadmap

| 当前结构 | 后续阶段 |
|---|---|
| 两个首页区域、三个私人空间概览、独立集合与全局 Search | 私人账户、实际收集与写入、统一索引 |
| 内容和关联的 Repository 接口，数据集合为空 | 在内容内显示关联、创建及管理可见性 |
| 品牌 Home、Activities、Stories、About | 活动详情、报名、内容发布与授权 |
| 原生 JavaScript、CSS、Hash Router | 原 Dashboard、Wiki、题库及正式公开网站的逐步接入 |

1. 将此原型仓库作为共享代码入口。在 Cloudflare 配置独立的受保护预览，确认访问边界后再发布正式版本。
2. 需要真实数据时先加 Worker API 与身份校验，再按权限分开私有读写与公开查询。D1 先承载结构化内容及关联，R2 承载附件。前端 Repository 替换成 API 实现。AI 接入使用具名、限权 API，生产写入由人确认。
3. 从原私有 GitHub 仓库复制并固定提交。先在隔离环境整合导航和只读入口。Dashboard/Wiki 的浏览器备份先演练恢复，校验原 ID、历史、附件和关联；题库保留原站，在副本验证 D1/R2 和账户映射后再考虑接入。
4. 公开品牌独立部署，以批准的发布投影和授权媒体作为输入。分阶段增加报名与反馈，反馈回流至私人空间。公开品牌及页面增加时沿用注册表，保持独立权限和数据边界。

主要风险是把 Demo 里的界面标签误当访问控制、把私人内容编进静态资产、把创作完成当公开授权，以及切换 origin 后遗漏本机存储。先验证发布隔离与备份还原，再接真实数据。
