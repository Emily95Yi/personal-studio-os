# Inbox 分类与连接恢复修复

## 已确认的故障

2026-11-18 23:58（东京时间），只读观察现有 `yistudio-private` Worker，并重新加载浏览器中已经失败的 Inbox 详情页：

- `/api/studio?revision=-1`、Inbox 单条读取和 Planner 请求正常完成。
- `/api/capture/options` 返回 `Exceeded CPU Limit`，Worker 报告 `Worker exceeded CPU time limit.`。
- 页面因分类选项读取失败而无法显示表单，只有“暂时无法连接 Studio，请稍后重试。”。

因此，至少这一轮故障来自分类接口的处理预算，单纯刷新不会消除原因。分类选项和分类写入原先都读取完整 Studio 快照；分类校验还会重新扫描全部附件的 Base64。原先的首次连接失败也无法通过后续轮询恢复。

## 本次修复

1. 每个新 R2 快照配套生成一个轻量目录，保留记录、附件元数据和图片签名前缀。分类选项和分类写入优先读取它，避免装载和解码原图。目录和快照使用同一个不可变对象键关联，并在新快照发布前准备完成；按既有策略保留的快照也保留对应目录。
2. 旧快照继续兼容。成功读取主数据时后台补建目录；缺少目录时可通过旧快照读取必要的元数据。分类仍检查标签、附件引用、跨模块关系和记录完整性，复用已在保存时验证的附件。
3. 读取请求对网络异常、超时和临时服务错误有限重试。保存请求不自动重放，避免响应丢失后重复写入。
4. 首次连接失败后继续尝试恢复，失败退避至最多一分钟。页面重新可见、窗口聚焦和网络恢复也会触发检查；可手动“重新连接”。登录过期时显示新窗口登录入口，保留原页表单。
5. Inbox 详情和列表增加原页“重试”。分类成功后明确显示目标模块，提供目标记录入口，并说明 Inbox 原条目按现有设计保留。分类回执与目标列表刷新分开处理，列表未读取成功时可再次读取。
